Security Policy - Vulnerability Disclosure Policy and Bug Bounty Program
Scope
This program covers the servers and the web, desktop and mobile applications developed by AirVPN. The following websites are included:
airvpn.org
eddie.website
ipleak.net
The AirVPN applications for Windows, macOS, GNU/Linux and Android are also included. AirVPN software is free and open source. Eddie, the AirVPN client for Windows, macOS and GNU/Linux, is released under the GPLv3 license, and its source code is available on GitHub: https://github.com/AirVPN/Eddie. The source code of Eddie Android edition and of the AirVPN Suite is available on GitLab: https://gitlab.com/AirVPN.
Rules
Responsible Disclosure: please report every vulnerability to security@airvpn.org. Participants agree not to disclose a vulnerability until it has been fixed, and to coordinate any disclosure with our team. Before transmitting any information about a vulnerability, please send us your GnuPG public key and use ours, published below, so that the whole communication remains confidential.
Responsible Testing: do not crack user accounts, corrupt databases or leak data that may be sensitive. Testing that degrades the quality of service for our users is not allowed. If in doubt, please contact our Security Team at security@airvpn.org before testing.
Adherence to Rules: by participating in this program, you agree to the rules and conditions on this page. A report is eligible for a bounty only if all of them have been followed.
Qualifying Vulnerabilities
Any design or implementation issue that substantially affects the confidentiality or the integrity of user data is within the scope of the program. This includes, but is not limited to:
Web applications
Cross-site scripting
Cross-site request forgery
Mixed-content scripts
Authentication or authorization flaws
Server-side code execution
REST API vulnerabilities
Servers
Unauthorized shell access
Privilege escalation
Remote code execution
Applications
Authentication or authorization flaws
Local data security breaches
Non-Qualifying Vulnerabilities
The following are not eligible for a bounty:
Flaws that affect only out-of-date browsers
Security issues outside the AirVPN threat model or service scope
Phishing or social engineering attacks
Bugs that require exceedingly unlikely user interaction
Out-of-date software
Software bugs in OpenVPN
Reports from automated scanners without a demonstrated impact
Missing security headers and Content Security Policy hardening
Version or banner disclosure
User name or e-mail address enumeration
Vulnerable third-party libraries without a working exploit against our services
Credentials stolen from users' devices, for example infostealer logs
SPF, DKIM and DMARC configuration
Rate limiting
Reward Amounts
Only very high risk and critical vulnerabilities are eligible for a bounty. The severity is assessed by AirVPN, case by case, with a DREAD-like scoring; a severity or CVSS score computed by the reporter is not binding. To be awarded a bounty, you need to be the first person to report the issue, and our team must be able to reproduce it from your report.
very high risk vulnerability, 250 EUR
critical vulnerability, 300 EUR AT LEAST
Examples of very high risk and critical vulnerabilities include:
remote code execution or unauthorized shell access on our servers;
access to other users' accounts or data without their interaction;
privilege escalation to root or Administrator through AirVPN applications;
exposure of the user's real IP address or traffic while the VPN is connected.
Reports of lower severity issues are still welcome: we evaluate them and fix them when appropriate, but they are not eligible for a bounty.
Reporting Guidelines
Please report issues to security@airvpn.org. Each report must include clear instructions to reproduce the issue, a proof of concept, or both.
